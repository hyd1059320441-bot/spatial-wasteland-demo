# V6：从进入游戏到完成第一段任务的体验

用户反馈：第一人称与环境比例不一致；加载很长；进入前后的场景不同；迭代缺少可感知进步。
用户已授权增加具体需求并直接实施。本文件是实施与验收依据，不是已完成声明。

## 1. 人体尺度与空间一致性

- 游戏空间1米必须对应真实移动1米。先核对Stage/SpatialView/游戏root的实际变换和追踪坐标，
  再校准视点；不能继续靠单独降低眼位修饰环境比例。
- 角色眼位、枪械、机器人、门、护栏、掩体和补给必须共用一套尺度基准。
  常用胸前掩体目标0.9～1.2米，护栏约1.05米，普通通行开口约2.1～2.4米；
  起重机、仓储厂房等大型工业结构保留合理用途所需尺寸。
- 出生区维修棚和常用货箱采用保持比例的模型缩放。允许变形的模块应明确标注；
  不能为了填满任意碰撞框，把所有模型的XYZ独立拉伸。
- 眼位校准必须有追踪有效性和坐标空间证据；保留真实蹲起、头向移动、转向及手柄枪械对应。
  用户视点偏好可调整，但不得改变世界尺度或让胶囊高度影响镜头。
- 验收：实际运行bounds、通行净高、碰撞尺寸和可接近路径一致；修复前后记录具体数值。
  数值检查不等同于真人头显的比例感验收。

## 2. 加载与场景生命周期

- 从第一个显示的游戏环境开始，就使用最终出生点和相同世界坐标。
  不展示未完成摆放的模型，再突然移动整个地图。
- 加载中的UI显示真实阶段与进度，且退出立即可用。未准备好的战斗不能自动开启。
- 把耗时分为Stage创建、资源、场景/碰撞、导航、可操作五段，日志记录单调时钟。
  至少测3次全新进程启动；缓存命中和首次生成分别报告。
- 实施目标：正常启动到可操作中位数不超过8秒，已生成有效资源/导航缓存的启动不超过5秒。
  目标必须由真机测量确认；达不到时记录具体超时阶段，不写“加载优化完成”。
- 静态导航可按SDK、布局、碰撞资源和胶囊参数的内容指纹缓存或预打包；
  不匹配、损坏或关键校验失败必须失效重建。保留原生碰撞与运行时扫掠。
- 出生区到战斗、死亡、重启不应销毁并重复导入相同资产。

## 3. 第一段任务必须让玩家感到变化

- 出生后能看到同一个真实战区、明确的局部目标和可交互对象；“开始”只改变任务状态。
- 第一段任务包含至少三种有区别的玩家行为：取用装备/补给、操作环境装置、应对战术敌人。
  顺序与反馈必须在世界内可理解，不能只有刷怪计数和远处摆件。
- 改造至少一个已有地标为有状态的任务装置：操作前后有真实动画/灯光/声音变化，
  并实际影响通路、敌人行为或补给。将其结果与主线或奖励关联。
- 加入一个多阶段战斗目标：能打断的装置/弱点、清楚的预警、阶段改变与明确结束反馈；
  不仅增加血量和怪物数量。
- 保留四波59敌人、最多18实例及既有奖励/双武器/退出契约；
  新机制须覆盖失败、死亡重试、暂停、重复交互和奖励后继续射击。

## 4. “有进步”的交付标准

- 交付记录逐项回答：玩家进入后看到了什么变化、能做什么新行为、加载节省多少、
  尺度修正了哪些对象；每项引用实际证据。
- 对照同一设备、同一任务段。GPU仍超预算时不能靠空场景、隐藏敌人或过度删画面来报好成绩。
- 单测数量、文件数量和新增资产数量不作为产品进步指标。
- 不自动提MeeGo，不改ROM，不升级公共SDK6.2.6，不要求用户提供头显截图。

## 已确认调查

- HomeStage在initialize前添加scene.root，模型加载期间逐个可见。
- WastelandScene在加载所有环境/武器/效果/18演员后才relocate出生点。
- 上次正常启动：资源/演员约5.5秒，导航9160采样耗时11947毫秒；
  从HUD初始化21:07:33.885到SCENE_READY21:07:51.420约17.5秒。
- EyeHeight默认1.55米；常用货箱掩体配置1.7～2.8米；维修棚5.5米。
  SceneKit.v3Asset默认exactSize=true，对模型XYZ分别缩放。
- 上一轮阴影实验没有改善帧数，已恢复正常完整投影；不能重复宣称该实验解决了性能。
